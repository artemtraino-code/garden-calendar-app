Живой интерфейс

Здесь уже не просто документ. Справа встроен сам интерфейс приложения. Можно сразу кликать, проверять механику и потом возвращаться к этому списку.

1. Лента

Проверь карточки, статус, структуру даты, работы, культуры, препаратов и заметок.

2. Календарь

Проверь плитки дат, скролл к дате, пустое состояние и цвет статусов.

3. Новое задание

Проверь единый шаблон формы, мультивыборы, график, препараты и заметки.

4. Редактирование

Проверь, что логика совпадает с новым заданием и не расползается по отдельным веткам.

5. Настройки

Проверь группы, культуры, работы, препараты и то, что всё реально опирается на них.

Что уже зафиксировано

Единый источник данных

Все справочники и формы должны опираться только на настройки: группы, культуры, работы, препараты.

Системные статусы

Запланировано, Выполнено, Пропущено участвуют в ленте, форме, плитках календаря и логике редактирования.

Единый multi-picker

Для групп, культур, работ и препаратов должен жить один паттерн: поиск, чекбоксы, выбрать все, chips, без схлопывания после выбора.

Batch-логика

Несколько культур и несколько работ не должны разрывать UI на пачку отдельных карточек. Это должен быть один связанный набор.

На что смотреть в первую очередь

Карточка ленты

Читаемость, иерархия, плотность, мобильная сборка.

Форма задания

Одинакова ли логика в новом задании и в редактировании.

Настройки

Все ли справочники реально управляют приложением, без скрытых списков.

Повторы и статусы

Понятно ли, как система ведет себя при повторе, пропуске и повторном назначении.

Что уже нужно перевести в компоненты +

Multi-picker

Один общий компонент для всех множественных dropdown-выборов в приложении.

Work form

Одна форма для нового задания и редактирования, без разъезда логики.

Timeline card

Один шаблон карточки с одинаковой внутренней структурой и адаптивной сборкой.

Status + repeat layer

Статусы, пропуски, повторить, повторять каждые, batch-связи — всё в одном системном слое.

Как сейчас принимать решения по интерфейсу +
Правильный режим работы дальше
  • Сначала открываем приложение.
  • Смотрим только одну зону: например, карточку ленты или форму задания.
  • Фиксируем, что именно устраивает, а что ломает UX.
  • Меняем только один слой за раз, чтобы не разваливать остальное.
Что не стоит больше делать
  • Не плодить отдельные одноразовые механики выбора.
  • Не хранить скрытые списки отдельно от настроек.
  • Не менять поведение формы только в одном экране, а в другом оставлять старую ветку.
Следующий нормальный этап разработки +
Этап 1. Архитектурная чистка
  • Вынести единый multi-picker.
  • Вынести единый work-form.
  • Вынести единый timeline-card.
Этап 2. Системный слой
  • Собрать status + batch + repeat в одном месте.
  • Убрать остатки временной логики из UI-обработчиков.
Этап 3. UI polishing
  • Финальная карточка ленты.
  • Финальная форма задания.
  • Проверка на desktop / tablet / mobile.
